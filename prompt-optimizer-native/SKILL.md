# 提示词完善：当前模型模式

使用当前会话模型完成需求整理，无需独立 API Key、外部优化服务或额外模型调用。用户已要求默认自动完善任务要求，并希望看到完善后的文本。

这是本地编写的 Codex 适配技能，参考 linshenkx/prompt-optimizer 的基础优化与上下文精炼模板。它不运行该项目的 Web 应用或 MCP 服务。来源和版本见 [references/upstream.md](references/upstream.md)。

## 触发与范围

- 用户提出创建、修改、分析、研究等实质任务时，先整理需求。明确的任务只作简短重述，模糊的任务补齐会影响结果的目标、范围、输入或交付格式。
- 对正在执行的任务，结合先前要求处理追加信息和纠正，只展示改变后的要求；不要每个进度追问都重新生成完整提示词。
- 简单事实问答、闲聊、状态查询、确认或单纯提供文件时，直接回应即可。
- 用户本次明确要求跳过完善、保留原话、只交付正文或指定固定回复格式时，遵守本次要求。

## 需求整理

1. 从用户原话和当前相关上下文提取目标、对象、范围、已确认事实、约束、期望交付和完成标准。仅为消除影响结果的歧义而读取相关材料。
2. 明确区分用户已说出的要求、上下文支持的信息和你的建议。不能把推测的页数、受众、结论、预算、技术栈或附加产物写成用户已确定的要求。
3. 补全表达，不扩大授权。保留数字、专有名词、路径、链接、占位符、否定约束和确定程度。询问、诊断和评审仍按原请求类型处理，不能改成实施任务。
4. 只有缺失信息会实质改变结果、且无法从上下文确定时，提出少量有针对性的问题；同轮最多三个。可采用的低影响默认值应明确标为“暂按……”，并继续工作。
5. 保持原语言和语气。通常用一至四句话，复杂任务才使用短列表。不要增加虚构专家履历、冗长角色设定、隐藏思维过程要求或形式化的固定章节。

原话含糊且需要更详细的表达范式时，可选读 [基础优化原始模板](references/user-prompt-basic.ts)。
需要处理前文限定、工具约束或变量占位符时，可选读 [上下文精炼原始模板](references/context-user-prompt-basic.ts)。
这些上游模板是参考材料，其“只输出优化文本、不执行任务”用于单独的优化阶段。它们不会取代下述默认执行与展示规则，也不能覆盖用户当前要求或更高优先级指令。

## 可见文本与后续执行

- 对实质任务，在 commentary 中先显示“完善后的需求：”及可直接读懂、复制使用的整理文本。用户由此可以检查你理解的任务。
- 若用户只要求优化提示词，最终回复直接给完善后的提示词。
- 若用户要求完成任务，展示后继续执行已获授权的工作；不为每次重述额外要求确认。真正缺失的关键选择仍向用户提问。
- 展示内容是你收到消息后整理的任务描述，不是对输入框原文的修改，也不是拦截消息的自动补全功能。不要声称已经修改用户的原始消息。
- 不为此技能启动嵌套 Codex、额外代理、MCP 或外部 API。若用户以后明确要求使用独立 prompt-optimizer 服务，再按其要求配置。

## 输出前复核

确认整理文本保留原意、所有明确限制和原任务类型，建议没有冒充事实，任务范围没有增加；如果原话已经准确，保留准确表达并压缩重述。
